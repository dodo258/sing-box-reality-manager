# 同类一键脚本调研：srm 凭什么值得用

日期：2026-10-11　按全局 `prior-art` 技能做。star、推送日期、release 都是当天用 `gh api` 查的。

## 怎么做的

- **看了谁**：
  - 直接同类 12 个：sing-box 和 Xray 的一键脚本，加上 Xray 官方安装器。
  - 相邻形态 7 类：Web 面板、Docker 部署、一体化方案、桌面 App 远程装机、纯手工、VPS 商家一键应用、买机场。
- **怎么看的**：
  - 每个仓库浅克隆后只读不跑，用 grep 和 sed 看安装入口、菜单和几个关键实现：证书、端口冲突、更新、卸载、迁移、订阅输出、防火墙、联网。下文的 `文件:行号` 对应当天克隆到的版本。
  - issues 用 `gh issue list --state all` 拉全，按评论数和关键词挑出来细看。
  - 可信度按 `feedback-triage` 判：能对上代码、多人多时间、描述具体的才算数；单条、空泛、推销竞品的单独标「可疑」。报告引用的 40 条 issue 都逐条用 `gh issue view` 核对过标题和状态。
- **口径**：
  - 「比 srm 强 / 弱」比的是 main 上的 v4 开发版。v4 还没发布，现网用户装到的仍是 v3。
  - 卖点只写代码和测试已经有的。

## 一句话结论

**srm 凭什么**：一键脚本里，目前只有 srm 把「不弄坏你的服务器」当成第一目标。

- 改任何东西都先校验，失败自动回滚。
- 只动自己加的东西，不偷偷联网。
- 新手回车两下就能拿到一个能直接导入各客户端、连得上的节点。

后面三节分别证明：这三件事同类都没做好；它们正是同类 issue 区里最多、最可信的抱怨（见「srm 凭什么」一节）。

## 二、逐个看：读代码和 issue 得出的具体结论

每个项目至少一条代码证据和一条 issue 证据。没读到的直接写「没读到」。

### 直接同类

**mack-a/v2ray-agent**（srm v3 就是从它魔改的）
- **代码**：
  - 核心更新先 `rm -f` 旧二进制再下载；不校验、不 check、不回滚（`install.sh:2478-2532`）。
  - 有 apt 进程时直接 `pgrep -f apt | xargs kill -9`（`:1265-1267`）；停 nginx 失败也 `kill -9`，会误杀 Docker 里的 nginx（#1339）。
  - 删端口跳跃规则时写死 `iptables -t nat -D PREROUTING 1`，删的是第 1 条，不一定是自己那条（`:3331-3334`）。
  - sing-box 端口只检查范围，不检查是否被占用（`:4018-4045`）。
  - 18 处把带 UUID 的链接拼进 `api.qrserver.com` 二维码地址（如 `:5023`）。
  - 生成的 Clash 配置开着 `external-controller: 0.0.0.0:9090`，没有 secret（`:9224-9230`）。
- **issue**：
  - 升级后坏了的约 40 条，例如 [#1247](https://github.com/mack-a/v2ray-agent/issues/1247)（27 评论）、#1092、#1203，官方的回答是卸载重装。
  - 于是有人要备份恢复：[#1240](https://github.com/mack-a/v2ray-agent/issues/1240)、#1265、#878。
  - [#1289](https://github.com/mack-a/v2ray-agent/issues/1289)：装 iptables-persistent 把 UFW 卸掉了。
  - [#757](https://github.com/mack-a/v2ray-agent/issues/757)：端口检测误报，5 人以上遇到。
  - 判定：可信。多人、跨 3 年，维护者自己也承认。
- **故意不做**：Shadowsocks（#921，怕封 IP）、ShadowTLS（#804）、sing-box 伪装站（#1142）。
- **比 srm 强**：功能广（CDN、多用户、订阅多机合并、DNS API 通配符证书）；社区和文档大；支持 CentOS 和 Alpine。

**yonggekkk/sing-box-yg**
- **代码**：
  - 第一问「开放端口并关闭防火墙」直接回车就是关：停 firewalld、`ufw disable`、`iptables -F/-X`、清 mangle 表，顺手停 apache（`sb.sh:178-210`）。
  - 依赖里装 `iptables-persistent`，这个包会把 UFW 卸掉（`:76`）。
  - 用行号 sed 改 JSON，比如 `sed -i "23s/…"`（`:2587-2651`），全脚本 60 处 `sed -i`，没有一处 `sing-box check`。
  - 卸载时清空整条 nat PREROUTING（`:3925`），Docker 的 DNAT 规则会一起没。
  - gitlab 订阅把 private_token 写进 URL（`:3264-3266`）。
  - 每天凌晨 1 点 cron 重启一次 sing-box（`:3812`）。
- **issue**：
  - 「卸载重装」出现在 41/281 条里，例如 [#304](https://github.com/yonggekkk/sing-box-yg/issues/304)，维护者答「老版本必须卸载重装」。
  - UFW 被卸：[#283](https://github.com/yonggekkk/sing-box-yg/issues/283)、[#214](https://github.com/yonggekkk/sing-box-yg/issues/214)（选了「否」也没了）。
  - 证书不续期：#100、#129、#139、#326。
  - 节点全是 -1、连不上的 14 条，多数是环境问题（NAT、厂商限 UDP），说明用户缺一个诊断手段。
  - 判定：可信，代码能解释原因。
- **故意不做**：Docker（#12）、自定义证书（#269）、DDNS（#264）。
- **比 srm 强**：Argo、WARP / Psiphon 多出口、视频教程和 TG 群，拉新手的能力极强。

**wulabing/Xray_onekey**
- **代码**：
  - 端口被占时，5 秒后对占用进程 `kill -9`；改端口时也走这段，用户输入的端口如果正被别的服务用，那个服务会被杀掉（`install.sh:393-413`）。
  - 直接停掉 firewalld、nftables、ufw；RHEL 上还关 SELinux（`:200-207`、`:324-328`）。
  - 改配置用 jq 写完直接 mv 覆盖再重启，不测试（`:440-446`）。作者在注释里自己承认，一个入站没证书的致命 bug 因此潜伏了两年（`:936-950`）。
  - 有一段注释提醒 acme.sh 的坑：`--install-cert` 漏写 `--reloadcmd` 就会把续期后的重载命令清空（`:800-805`）。
- **issue**：
  - 共 394 条，0 条 open，因为每隔一段时间批量关闭。
  - 证书相关 66 条，例如 [#477](https://github.com/wulabing/Xray_onekey/issues/477)，作者确认两个根因：续期时校验路径访问不到，`--reloadcmd` 被清空。
  - nginx 起不来 46 条，作者在 #469 承认是脚本自己 kill 掉的。
  - 可疑：#473「后门」只有一句话，没有证据。

**fscarmen/sing-box**
- **代码**：
  - 每次运行都向作者服务器上报一次统计（`sing-box.sh:567-577`、`:6600`）。
  - 机器上没有 xxd 时，把用户指定的 Reality 私钥明文发给作者的 API 去算公钥（`:4276`、`:4318`）。
  - 快捷命令 `sb` 每次都从 GitHub 拉最新脚本来跑，而且关了证书校验（`:5983-5993`）。
  - 默认装最新**预发布**核心（`:2546-2549`）。
  - 换核心时先用新二进制 `check` 现有配置，不通过就回滚（`:6401-6478`）。这一点做得好。
  - 改 UUID 或 SNI 时，对 `/etc/sing-box` 下所有文件全局 `sed`，不跑 check（`:1119-1128`）。
  - firewalld 下开端口跳跃，会把 public zone 的 target 永久改成 ACCEPT（`:2594-2606`）。
  - 订阅用 nginx 按 UA 返回不同客户端的格式（`:3872-3890`）。
- **issue**：
  - alpha 核心把新机装坏的 23 条，例如 [#175](https://github.com/fscarmen/sing-box/issues/175)，维护者说「我比较有冒险精神，坚持最新版本」。

  - [#353](https://github.com/fscarmen/sing-box/issues/353)（open）：iptables 规则追加在 REJECT 之后，不生效。
  - #303、#230：端口跳跃重启后失效。
  - 判定：可信，都能和代码对上。没有人专门反对遥测，但这个风险用户自己看不到。
- **故意不做**：配合宝塔等面板（#121）；默认用稳定版核心。
- **比 srm 强**：回车一次装 11 个协议 + Argo + 按 UA 适配的订阅；中英双语；支持 Alpine 和 Docker。

## 四、避什么（同类被骂的坑，srm 怎么不踩）

| 坑 | 谁踩了 | srm 的做法 / 要守住的线 |
|---|---|---|
| 升级不校验、不 check、不回滚，出了问题让用户卸载重装 | mack-a、yg、233boy、eooce、3x-ui、Hiddify | 用 Release digest 校验，先 check，原子切换，健康检查，失败回滚。**以后任何新功能都不能绕过这条流水线** |
| 默认装预发布核心，或打开菜单就自动更新 | fscarmen、Hiddify（凌晨 3 点自动更新）、Outline（Watchtower） | 只装稳定版；后台只查版本，用户手动更新。另补「大版本上限」（待做） |
| 关掉或卸掉用户的防火墙，清空整条链，规则加在 REJECT 之后 | yg、eooce、Xray_onekey、fscarmen #290 #353、TheyCallMeSecond、3x-ui | 不关、不清空、不装会卸掉 UFW 的包；规则插在兜底 REJECT 之前；只删自己加的；运行、停用、开机、卸载逐种情况测过 |
| `kill -9` 别人的进程，覆盖别人的 service，purge 别人的包 | mack-a、Xray_onekey、deathline94、caigouzi、passeway、Hiddify | 端口被占就报错，原服务不动；独立的服务名 `srm.service` 和路径 `/opt/srm`；卸载只删自己的 |
| 改系统设置不还原（时区、sysctl、resolv.conf、SELinux） | Hiddify、Amnezia、yg、TheyCallMeSecond、Xray_onekey | 系统设置只动 BBR，默认不动，用户选了才开；卸载时还原（`bbr_restore`）。以后新增系统改动必须同时写好还原 |
| 节点凭据交给第三方：在线二维码、订阅转换、算私钥、上报统计 | mack-a、Xray_onekey、fscarmen、eooce | 二维码本地生成；临时导入链接由服务器自己发，用完即关；没有遥测。外部请求只发生在必须联网的步骤：部署时查一次公网 IP（Cloudflare trace）、检测伪装目标、从 GitHub 查版本和下载（每日检查只查版本号）、acme 申请证书；节点凭据不离开服务器 |
| 打开菜单或查看节点要联网，请求不设超时 | 233boy、yg、fscarmen、Xray_onekey、reality-ezpz | 打开菜单不联网，所有 curl 都设超时（AGENTS 约定） |
| Reality 参数敷衍：short_id 为空或写死，目标固定列表或用 CF，所有人用同一个 SNI | eooce、passeway、233boy、Amnezia | 每个节点随机 short_id；候选在服务器上实测，排除 CF |
| 常驻的明文订阅端口或 Web 面板，默认凭据 | s-ui、3x-ui、fscarmen、yg | 不做常驻服务。临时链接走随机路径，下载一次或 10 分钟后关闭 |
| 每次运行都从 main 拉最新脚本来跑 | fscarmen、eooce、reality-ezpz、PasarGuard | 本地有固定版本，只在用户手动更新脚本时下载并校验 |
| 菜单和输出里打广告、推广 | mack-a、233boy、Xray_onekey、3x-ui、yg | 不打 |
| 端口自检用本机回环，误报「端口未开放」 | mack-a #757 | 不做本机回环自检，只提醒安全组 |

## 五、srm 凭什么

**一句话**：别的一键脚本是「装上就行」，srm 是「装上能用，而且绝不把你的服务器搞坏」。改任何东西都先校验、失败自动回滚；只动自己加的东西；不偷偷联网。新手回车两下，就能拿到能直接导入各客户端的节点。

要做到最好的三点。每一点都有同类的 issue 作反面证据，也有 srm 现有的代码和测试作正面证据：

1. **改了不会坏，坏了能回去**：下载校验、配置先 check、原子切换、健康检查、失败回滚；只装稳定版，只提示、手动更新。
   - 同类在这件事上的抱怨最多：mack-a 升级后坏了约 40 条；yg「卸载重装」41 条；fscarmen alpha 23 条；233boy #112、#120；TheyCallMeSecond #5；3x-ui 约 50 条；Hiddify #4592。
   - 12 个直接同类里，只有 fscarmen、TheyCallMeSecond、passeway 在换核心时先 check（passeway 换上后不能回滚），ArgoX 改配置前会 `xray run -test`。**没有一个在每次改配置时都做到 check、切换、健康检查、失败回滚**。
   - 还要补：大版本上限、凭据不轮换的测试、离线更新、换机导出导入。
2. **不越界**：只加只删自己的防火墙规则，按情况逐格测过；不关防火墙，不 kill 别人的进程，不改时区，不卸别人的包；卸载会还原；不上报，不打广告，打开菜单不联网。
   - 反面证据：yg #283 #214、fscarmen #290 #353、mack-a #1289、3x-ui #6569 #6776、Hiddify #4075、Amnezia 改 sysctl。
   - 12 个直接同类里，只有 fscarmen 做了防火墙规则的所有权记录，但它的 iptables 规则加在 REJECT 之后（#353 还开着），firewalld 下还会整区放行。
   - 还要补：公开「改了你系统的哪些地方」，识别别家脚本时只提示、不动。
3. **装完就能连上，连不上知道为什么**：Reality 目标实测后自动选；部署完一屏给全各客户端的写法和安全组提示；有临时导入链接；Hysteria2 有端口跳跃和证书 pin；UDP 受限时有说明。
   - 反面证据：233boy #98（SNI 用 CF）、#2（要端口跳跃，至今没做）；yg「-1」14 条；fscarmen #242（97 评论）；eooce 自签证书兼容 4 条；Amnezia 所有人用同一个 SNI。
   - 还要补：「连不上自查」。

**说不出来的地方（如实写）**：
- 功能广度、社区规模、视频教程、系统覆盖面（Alpine、CentOS），srm 都比不过 mack-a、yg、fscarmen。
- 零提问部署，233boy、eooce、passeway 已经做到；srm 是两次回车，算同一档。
- 这些都不是 srm 的卖点，也不追。
- v4 还没发布、没有外部用户，上面的卖点目前只在 CI 和主人的 Lisa 上验证过，还没有真实用户的反馈。

## 六、明确不做（防缝合怪）

| 不做 | 谁有 | 理由 |
|---|---|---|
| Web 面板、多用户计费、到期、流量配额 | 3x-ui、s-ui、Hiddify、PasarGuard | 一台 VPS 自己和家人用，用不上这些，却要背上常驻端口、默认凭据、数据库、200 MB 以上的内存。s-ui 维护者也说多节点是「商用需求，会让个人面板变重」（#1266） |
| 常驻订阅服务 | mack-a、fscarmen、yg、eooce、s-ui | 常驻的明文端口会被扫。v4 已改用「完整配置导出 + 临时导入链接」 |
| Xray 双核 | mack-a、ArgoX | 双核是 v3 臃肿的主要来源（见方案「为什么重写」） |
| Argo 隧道、WARP、Psiphon、CDN 优选 | yg、fscarmen、eooce、mack-a | 依赖第三方账号或 API，坏起来最频繁（yg WARP、reality-ezpz #207、Hiddify #4047），而且和「部署一个能用的节点」无关 |
| Docker 形态 | reality-ezpz、Outline、Amnezia、teddysun | 发布的端口绕过 UFW；`latest` 会静默升级；镜像拉不下来；OpenVZ 跑不了；端口跳跃要 host 网络。srm 原生 systemd 已经有回滚和迁移 |
| 自动更新 | Hiddify、Outline | 会断网，出事时用户不在场（Hiddify #4592、Outline #1501） |
| 默认装预发布核心 | fscarmen | alpha 相关 23 条 |
| Serv00、PaaS、无 root 环境 | eooce | 另一批用户，平台本身就会杀进程 |
| 中转 / 落地生成器 | caigouzi | 进阶需求；srm 先把单机做好。有需求再评估 |
| 伪装网站 | mack-a、Xray_onekey | v4 方案已删除，理由见方案 |
| 遥测、广告、推广 | fscarmen、mack-a、3x-ui、233boy | 违背「不越界」 |
| 本机回环自检「端口通不通」 | mack-a | 会误报（#757）。只提示安全组 |
