# sing-box-reality-manager v4：重写方案

日期：2026-10-10　状态：已定（Claude 拍板，2026-10-10 按主人补充的方向修订；正式发布见「待主人确认」）

## 为什么重写

主人原话：「脚本不像脚本，工具不像工具，在 Linux 上运行时又卡顿，里面还有很多多余的内容。」

现状（v3.8.4，2026-10-10 静态分析，行号指 `install.sh`）：

- **一个 14851 行的 `install.sh` 装下所有逻辑**：362 个函数，至少 27 个从入口走不到。Xray 和 sing-box 两套安装和配置生成并存（`initXrayConfig` 463 行、`initSingBoxConfig` 471 行）。网站和博客功能 50 个函数、1702 行，HTML 直接写死在脚本里。`fodder/` 有 35MB 网站模板 zip。上游遗留的 VMess、Trojan、Tuic、Naive、gRPC、WARP、宝塔、CDN 代码大量残留。
- **卡顿**：
  - 启动要起 180–250 个子进程，比如 `find /etc -name redhat-release` 和 `readInstallProtocolType` 里成串的 `echo|grep`。
  - 看账号时，每条链接要 curl 3 次 cloudflare 查公网 IP，没设超时。
  - 44 处 curl 里有 38 处没设超时。
  - 每次安装都跑 `apt update`，还会 `kill -9` 掉 apt。
  - `handleSingBox restart` 每次 stop、sleep、start，至少 2 秒，一次安装要重启好几次。
  - 每做完一个操作就退出，要重新输 `vasma`，启动检测再跑一遍。
- **不像工具**：
  - 没有命令行子命令，也没有 `--help`；`$1` 只认 3 个定时任务名。
  - 196 处 `read -r -p` 只有 23 处提示了默认值。
  - 200 处 `exit 0` 对 1 处 `exit 1`，出错也返回成功。
  - 不检测终端，颜色码到处打。
- **安全和隐私**：
  - 二维码走第三方 `api.qrserver.com`，UUID 和公钥会传出去。
  - Clash 模板的规则地址走第三方 `gh-proxy.com`。
  - BBR 直接下载并执行第三方的 `tcpx.sh`。
  - Reality shortId 所有部署都写死为同一个值。
- **发版没在工作**：
  - `create_release.yml` 只在推送 `master` 时触发，而默认分支是 `main`，所以一次都没运行过。
  - 自更新先 `rm` 掉自己再下载 main 分支的 raw 文件，下载失败 `vasma` 就成了断链。

主人另写的 `dodo-sbox`（~/projects/dodo-sbox-next，私有，约 1230 行）已经把这些问题解决了一遍：
- 多文件模块化，用 `build.sh` 打包成单文件；
- 安装和更新都从 Release 下载，并校验 SHA256；
- `state.json` 是唯一数据源，配置按「用 jq 生成 → `sing-box check` → 原子切换 → 健康检查 → 失败回滚」的流程上线；
- 有命令行子命令，菜单常驻，打开菜单不联网；
- CI 跑 shellcheck、隔离环境里的真实 UFW 和 systemd 测试。

v4 就以它为骨架。

## 目标与验收

1. **快**：
   - 打开菜单不联网，子进程不超过 15 个，在 1 核 VPS 上 0.3 秒内出菜单；
   - 看账号和链接不联网，公网 IP 部署时写进 state，可以手动刷新；
   - 改配置只重启一次服务，失败自动回滚；不自动更新，避免意外断网。
2. **像工具**：
   - 每个功能都有非交互子命令，`--help` 列出全部；
   - 退出码有意义（成功 0，失败非 0）；
   - 输出不是终端或设置了 `NO_COLOR` 时不带颜色；
   - 菜单常驻，做完一件事回到菜单，任何一步输入 0 返回；
   - 交互提问都给默认值，回车即默认。
3. **干净**：
   - 除 Snell 外都由 sing-box 一个核心、一个 systemd 服务承担，Snell 用官方 `snell-server` 单独跑；
   - 仓库里没有网站模板、没有上游残留协议、没有第三方执行脚本；
   - 二维码在本地生成（`qrencode`，没装就只给链接）。
4. **不丢老用户的节点**：`srm migrate` 把 v3 的 sing-box 节点（Reality、AnyTLS、Hysteria2，UUID、密钥、端口、证书都保留）转进新 state，旧目录原样留作备份。
5. **可验证**：CI 跑 `bash -n`、shellcheck、重新构建后 dist 无差异、单元测试和隔离环境集成测试（沿用 dodo-sbox 的做法），合并前必须全绿。

## 功能取舍

**2026-10-10 主人补充的方向**（以此为准）：
- sing-box 能部署的服务端协议全部支持；
- Snell 不放进 sing-box，单独部署（主人在 Surge 上主要用 Snell + ShadowTLS）；
- 外部用户最常用的是 VLESS，其次是 Hysteria2、AnyTLS，部署流程要照顾到所有用户，并且简单；
- 各协议的核心能更新到最新版本（后来主人补充：更新会断网，所以只提示、手动更新，见「更新」一节）。

### 协议

依据 sing-box 官方文档的 inbound 列表（2026-10-10 查，稳定版 1.14.3）。v4 支持其中所有「对外提供代理服务」的协议：

| 协议 | 需要域名证书 | 菜单位置 | 说明 |
|---|---|---|---|
| VLESS + Reality | 否 | **推荐首选** | 默认方案，回车即部署 |
| Hysteria2 | 否（无域名用自签证书 + pinSHA256） | 常用 | 弱网、丢包环境 |
| AnyTLS | 是 | 常用 | |
| Snell v6（可选 v5）+ ShadowTLS v3 | 否 | 常用（Surge 用户） | 见下文 |
| Shadowsocks 2022 | 否 | 更多协议 | 可单独用，也可套 ShadowTLS |
| TUIC v5 | 是（或自签） | 更多协议 | |
| VLESS + TLS（tcp / ws / grpc / httpupgrade） | 是 | 更多协议 | ws 等可以套 CDN |
| Trojan（TLS） | 是 | 更多协议 | |
| VMess（TLS + ws） | 是 | 更多协议 | 兼容老客户端 |
| Naive | 是 | 更多协议 | |
| Hysteria（v1） | 是（或自签） | 更多协议 | 只为兼容老客户端，菜单里标注 |

不做：`direct`、`mixed`、`socks`、`http`、`tun`、`redirect`、`tproxy`。这些是本地代理或透明代理用的，不适合公网部署。`cloudflared`、`tailcat`、sing-box 自带的 `snell` 放进「以后再说」。

### Snell + ShadowTLS（单独部署 Snell）

- **Snell 服务端**用 Surge 官方的 `snell-server`，作为独立的 systemd 服务 `srm-snell@<节点id>`，只监听 `127.0.0.1`。
  - **默认 v6**。2026-10-10 查 Surge 官方发布说明（kb.nssurge.com/surge-knowledge-base/release-notes/snell）：最新是 `v6.0.0rc2`，v6 还没有正式版。v6 新增按 PSK 区分每个部署的流量特征和 `mode` 流量整形（`default` 混淆加 AES，`unshaped` 只用 AES、吞吐约高 10%，`unsafe-raw` 不加密）；去掉了 QUIC 代理模式。服务端和客户端的 mode 必须一致。
  - `mode` 默认用 `default`，部署时可以改选 `unshaped`；`unsafe-raw` 不提供。
  - **可选 v5**，给还没升级到支持 v6 的客户端用（官方没说 v6 服务端是否兼容 v5 客户端，所以不假设兼容）。
  - 下载地址：`https://dl.nssurge.com/snell/snell-server-v{版本}-linux-{amd64|aarch64}.zip`。
  - 官方没有给出 v6 的服务端配置示例。实现时要用下载到的二进制实测配置项（`snell-server --help` 或它的向导输出），确认 `mode`、`ipv6` 等写法，不能凭猜。
- **ShadowTLS v3 前置**用 sing-box 的 `shadowtls` inbound，`detour` 到一个 `direct` inbound，再用 `override_address`/`override_port` 转发到 `127.0.0.1:<snell端口>`。这样不用再装 shadow-tls 二进制，前置也能享受 sing-box 的配置校验和回滚。实现时要先实测这条链路，跑不通再退回独立的 `shadow-tls` 二进制，并把原因写进 DECISIONS。
- **为什么不用 sing-box 自带的 snell inbound**：sing-box 1.14 起虽然有 snell inbound（支持 v5、v6），但它是重新实现的，官方 `snell-server` 是参考实现，跟 Surge 的新版本最同步；主人要求 Snell 单独部署。
- **输出**：直接能粘贴进 Surge 的配置行（含 `version=`、v6 的 mode 和 `shadow-tls-password`、`shadow-tls-sni`、`shadow-tls-version=3`；v6 的具体参数名以 Surge 官方文档为准，实现时查证并在代码注释里写明出处），另附 Clash Meta (mihomo) 的写法（mihomo 不支持 v6 就写明只给 v5）。

### 其他功能

| v3 功能 | v4 | 理由 |
|---|---|---|
| 多实例 Reality / AnyTLS | **保留，形式改变** | state 里同一协议可以有多个独立节点，不再单开菜单 |
| 节点级 DNS 分流、流媒体分流 | **保留** | policies 加 `inbounds` 字段，可以限定到具体节点 |
| 证书申请和续期、BBR、防火墙提示、更新与回滚、卸载 | **保留** | 用 dodo-sbox 的实现；BBR 用内核自带的 sysctl，不下载第三方脚本 |
| Xray 核心 | **删除** | 双核心是臃肿的主要来源；上面的协议全由 sing-box 提供 |
| WARP / 宝塔 / CDN 优选 / BT 屏蔽等杂项 | **删除** | 上游残留，和节点部署无关 |
| 网站管理（博客、工具站、伪装站、`fodder/`） | **删除** | 和节点管理无关，占了 1700 行和 35MB；建网站请用正常的 Web 服务器 |
| nginx 订阅服务（`subscribe*`） | **删除** | 改为导出原始链接、二维码和各客户端的配置片段；v3 的订阅链接会失效，README 写明 |

## 部署流程（照顾所有用户，越简单越好）

第一次运行 `srm`（还没有节点）直接进「快速部署」：

```text
  1. VLESS Reality      推荐 · 不需要域名 · 回车即可
  2. Hysteria2          弱网/丢包环境 · 不需要域名
  3. Snell + ShadowTLS  Surge 用户
  4. AnyTLS             需要域名
  5. 更多协议…          SS2022、TUIC、Trojan、VMess、VLESS+TLS、Naive、Hysteria
```

- 每个协议最多问 2 个问题，都有默认值，回车即用默认：
  - 端口：默认随机挑一个空闲端口；
  - 节点名：默认「协议-地区」。
- 只有需要证书的协议才问域名。问之前先检查域名是否解析到本机，解析不对就当场提示，不等申请证书失败才报错。没有域名的用户，只把不需要域名的选项排在前面。
- Reality 的目标站点自动从内置列表里挑一个，并检查 TLS 1.3、HTTP/2 和证书链，用户不用自己找。
- 部署完一屏给全：
  - 原始链接和本地生成的二维码；
  - 云服务器安全组需要放行的端口和协议（tcp/udp）；
  - 按客户端分好的配置片段：Surge、Clash Meta、sing-box、Shadowrocket、v2rayN。只给该协议支持的客户端。
- 非交互用法：`srm add <协议> [--port N] [--domain D] [--name X] [--yes]`。适合写进自己的初始化脚本，输出同上；加 `--json` 时输出机器可读格式。
- 已有节点时，`srm` 打开常驻菜单，第 1 项就是「添加节点」，进入同一套流程。

## 更新（手动更新，后台只做提示）

主人 2026-10-10 定：更新核心要重启服务，会短暂断网，所以**不自动更新**，由用户手动更新。

- **后台检查**：每日一次的 systemd timer（凌晨随机时刻）**只查版本号**，结果写进 `/var/lib/srm/update-check.json`。它不下载、不替换、不重启，对连接零影响。`srm update-check on|off|status` 控制开关，默认开。
- **提示**：打开菜单时从 `update-check.json` 读结果（不联网），有新版本就在顶部状态栏显示「sing-box 1.14.3 → 1.14.4 可更新」。`srm status` 也显示。
- **手动更新**：`srm update`（或菜单「更新」项）。执行前先提示「更新需要重启服务，所有连接会断开几秒」，确认后才开始；`--yes` 跳过确认。可以单独更新：`srm update core|snell|script`。
- **sing-box**：
  - 只装最新的**稳定版**（不装 alpha、beta、rc）；
  - 用 Release API 返回的附件 `digest`（sha256）校验，沿用 dodo-sbox `lib/system.sh` 的做法；
  - 新二进制先对当前配置跑 `sing-box check`，通过才替换；
  - 重启后做健康检查，失败就自动换回上一版并提示。
  - 最低支持 1.14。
- **snell-server**：
  - 跟随节点所选的大版本（默认 v6），取该大版本的最新构建，版本号从官方发布说明中解析。这个大版本还没有正式版时（比如 v6 目前只有 RC），就跟随最新的 beta/RC；出了正式版以后只跟正式版；
  - 官方不提供校验和，下载后先运行一次核对版本号，再重启和健康检查，失败就回滚。
- **脚本自身**：从 Release 下载，校验 SHA256，失败保留原版本。替换脚本本身不需要重启服务。
- **其他会重启服务的操作**也要事先提示会短暂断开：添加、删除、修改节点，改分流。手动操作时显示一句提示即可，不用二次确认。

## 架构（照搬 dodo-sbox，改名）

```text
lib/*.sh       模块：common config protocols system firewall certificates routing menu updates migrate main
build.sh       按固定顺序拼成 dist/srm，跑 bash -n，生成 dist/SHA256SUMS
srm.sh         开发入口，直接 source lib
install.sh     引导：从 Release 下载 srm 和 SHA256SUMS，校验后执行 `srm install`
tests/*.sh     沿用 dodo-sbox 写法：用同名函数替换 systemctl 等命令
```

- **命令**：`srm`，同时装一个 `vasma` 软链兼容老习惯。
- **服务器路径**：`/opt/srm`（脚本、核心、acme.sh），`/var/lib/srm`（state、generations、证书、防火墙所有权记录）；服务名 `srm.service`，系统用户 `srm`。
- **协议注册表**（`lib/protocols.sh`）：每个协议一组函数，`proto_<type>_{validate,render_inbound,share_uri,client_outbound,transport,prompt}`。`validate_state`、`render_config`、防火墙同步、健康检查都通过注册表分派，不再在各处写 `case` 和「hysteria2 用 udp」。以后加协议只新增一个文件段。
- **state**：
  - schema 升到 2；
  - 节点加 `transport`；
  - policies 加可选的 `inbounds`；
  - 端口范围放宽到 1–65535（仍然检查占用；默认随机在 10000–50000）；
  - 写好 schema 1 到 2 的迁移函数。
- **核心版本**：安装时取最新稳定版（最低 1.14），之后按「更新」一节每日只检查版本、由用户手动更新；下载都要校验，沿用 dodo-sbox 的 `core_download` 和 Release digest 校验。
- **Reality**：shortId 每个节点随机生成；部署前用 `reality_target_check` 检查目标站点。
- **兼容 v3 的定时任务**：老服务器的 crontab 里写着 `/etc/v2ray-agent/install.sh RenewTLS|UpdateGeo|WebsitePublish`。v3 的「更新脚本」会把 main 分支的根目录 `install.sh` 下载到这个路径，所以新的引导 `install.sh` 收到这 3 个参数时，必须输出一行迁移提示并退出 0。不能报错，也不能去执行安装。

## 迁移（`srm migrate`）

- 读 `/etc/v2ray-agent/sing-box/conf/config/*.json` 里的 sing-box inbounds（包括 `30_`–`33_` 多实例文件）、`.key`/pin 文件、`tls/` 证书和 `snell-shadowtls/nodes/*.env`，凡是 v4 支持的协议都迁过来，生成 schema 2 的 state。
- 默认 dry-run，列出「将迁移的节点 / 无法迁移的内容（Xray 核心的节点、网站、订阅）」；加 `--apply` 才执行。
- 执行时：
  - 先停掉旧服务 `dodo258-sing-box`、`dodo258-xray`、`dodo258-snell-*`、`dodo258-shadowtls-*`，以及上游的 `sing-box`/`xray`；
  - 再用新服务原样监听原端口，健康检查失败就恢复旧服务；
  - 把旧的 crontab 行注释掉，不删；
  - `/etc/v2ray-agent` 一个字节都不动。
- 测试：用几份脱敏的 v3 配置样本放在 `tests/fixtures/v3/`，断言迁移出来的 state 和期望一致。

## 拆分（按顺序做，每条都能单独合并，合并后 main 上仍是可用的 v3）

1. 骨架：搬入 dodo-sbox 架构和协议注册表，支持 Reality、AnyTLS、Hysteria2，加命令行、常驻菜单和 CI。新代码不碰根目录 `install.sh`。
2. 多节点和节点级分流：schema 2、同协议多节点、policies 加 `inbounds`。
3. 补齐 sing-box 其余服务端协议（「协议」表里除 Snell 以外的全部）。
4. Snell v6（可选 v5）+ ShadowTLS v3：官方 `snell-server` 单独部署，sing-box 负责 ShadowTLS 前置。
5. 更新：后台每日只检查版本并在菜单提示，用户手动更新（会断网，先提示），带校验和回滚。
6. 快速部署流程和客户端配置片段（「部署流程」一节）。
7. `srm migrate`，附 fixtures 测试。
8. 切换发布（等主人确认）：根目录 `install.sh` 换成新引导并兼容 v3 定时任务；旧脚本移到 `legacy/v3`；删 `fodder/` 和过时的 documents；重写中英文 README；发版工作流改成按 tag 触发、上传附件、不删旧 release；发 v4.0.0。
